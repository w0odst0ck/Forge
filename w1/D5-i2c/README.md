# W1-D5 · I2C 读 MPU6050 六轴传感器

> 验证标准：串口每秒打印加速度/陀螺仪/温度读数，改仿真值能跟上

> 注：原计划用 BME280，但 Wokwi 部件库没有它（137 个部件里 I2C 传感器只有 MPU6050 和 DS1307）。MPU6050 是更经典的 I2C 教学设备——地址、寄存器、总线机制完全一样，技能通用。

## 操作步骤

1. `sketch.ino` 粘贴到 Wokwi 代码编辑器
2. 新建 `libraries.txt`，粘贴依赖库三行（见下）
3. `diagram.json` 粘贴生成电路：ESP32 + MPU6050
4. 点 ▶ 运行：Serial Monitor 每秒输出加速度/角速度/温度
5. 点一下仿真里的 MPU6050 部件 → 修改 `accelX/rotationX/temperature` → 看串口跟着变


## 电路

```
ESP32 3V3 ── MPU6050 VCC
ESP32 GND ── MPU6050 GND
ESP32 D21 ── MPU6050 SDA   (数据线)
ESP32 D22 ── MPU6050 SCL   (时钟线)
```

- I2C 只需 **2 根线**（SDA 数据 + SCL 时钟）就能挂一堆设备，靠**设备地址**区分
- ESP32 默认 I2C：SDA=D21, SCL=D22（`Wire.begin(21, 22)` 可改）

## 概念速记

| 概念 | 要点 |
|------|------|
| I2C | 两线制同步总线：SCL 提供时钟，SDA 传数据。主设备发起，从设备应答 |
| 设备地址 | 每条总线上每个设备一个 7bit 地址。MPU6050 出厂 0x68，**AD0 接高电平变 0x69** |
| 寄存器 | 传感器内部寄存器表（加速度/陀螺仪/温度/配置），主机按地址读写 |
| 上拉电阻 | I2C 是开漏总线，需要上拉电阻（Wokwi 的 MPU6050 内置）|
| 库封装 | Adafruit 库把寄存器级操作封装成 `getEvent()`——先用起来，再看库源码理解寄存器 |
| 六轴 | 3 轴加速度 + 3 轴角速度。加速度计测"倾斜/震动"，陀螺仪测"旋转速度"，融合 = 姿态 |

## 面试式验证问题

1. **I2C 和 UART 的本质区别？**（I2C：同步+时钟线+多设备寻址；UART：异步+波特率+点对点。I2C 总线可挂多个设备，UART 一般一对一）
2. **MPU6050 地址 0x68 和 0x69 怎么选？**（由 AD0 引脚电平决定：接地=0x68，接高=0x69。同一总线挂两个 MPU6050 时分别设 AD0，就能共存——这是 I2C 设备"地址可配置"的典型例子）
3. **一条 I2C 总线上两个设备地址相同会怎样？**（总线冲突：两个从设备同时应答，数据错乱。地址冲突是 I2C 联调经典故障）
4. **SDA/SCL 为什么要上拉电阻？**（开漏结构：设备只能拉低，不能主动拉高；上拉电阻把线"默认拉高"，谁拉低谁说话）

## 组合挑战（D4+D5 合体，W2 预演）

- **传感器数据上串口**：把 MPU6050 的温度用 `Serial2` 发出去（`Serial2.printf("T=%.1f\n", temp.temperature)`）
- 这就是"传感器 → 通信 → 上位机"的数据链路雏形。W2 会把这条链换成 Modbus 协议，让 PC 用标准协议读懂灯具状态（灯具在 Modbus 里的地位 = 这里的传感器）
