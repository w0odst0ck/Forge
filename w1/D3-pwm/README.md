# W1-D3 · PWM 调光（LED 亮度渐变）

> 验证标准：LED 亮度平滑渐变（呼吸灯效果）；逻辑分析仪看到 PWM 波形占空比变化

## 操作步骤

1. `sketch.ino` 粘贴到 Wokwi 代码编辑器
2. `diagram.json` 粘贴生成电路：ESP32 + LED + 电阻 + **逻辑分析仪**（接 D2 观察波形）
3. 点 ▶ 运行：LED 从暗到亮再到暗循环（呼吸灯）
4. 打开 **Logic Analyzer**（仿真窗口底部 tab）→ 选择 D2 通道 → 看到方波，占空比随时间变化
5. 把 `PWM_FREQ` 改成 1000 → 看波形变疏；改成 10000 → 变密

## 电路

```
ESP32 D2 ── 220Ω ── LED(阳极) ── LED(阴极) ── GND
逻辑分析仪 CH0 ── D2（并联观察，不干扰电路）
```

## 概念速记

| 概念 | 要点 |
|------|------|
| PWM | 脉冲宽度调制：快速开关引脚，用"高电平占一个周期比例"（占空比）模拟模拟输出 |
| 占空比 | 高电平时间 / 周期。0% = 全灭，100% = 全亮，50% = 视觉半亮 |
| 频率 | 每秒开关次数。**≥3kHz 人眼无闪烁**（低频 PWM = 频闪源头 → W3 深挖）|
| 分辨率 | 占空比的细分粒度，8bit = 0-255 共 256 级 |
| LEDC | ESP32 硬件 PWM 外设（LED Control），可配 16 通道，频率/分辨率独立 |
| 呼吸灯 | 占空比从 0 平滑扫到 255 再扫回，人眼感知为"渐亮渐暗" |

## 面试式验证问题

1. **PWM 调光为什么"看着像"模拟调光？**（开关频率远高于人眼/灯响应，视觉积分平均亮度 = 占空比 × 满亮度；原理同显示器刷新）
2. **LED 为什么不能直接靠改变电流调光？**（色温偏移 + 驱动电路复杂；PWM 恒流调光色温稳定——但低频会频闪，所以真实驱动用 ≥3kHz 高频 PWM 或 CCR 恒流调光）
3. **分辨率 8bit 和 16bit 差在哪？**（256 vs 65536 级；低亮度段 8bit 的步进肉眼可见"跳变"，16bit 平滑——高端调光驱动的重要参数）
4. **`ledcWrite` 和 `digitalWrite` 区别？**（digitalWrite 只有 0/1；ledcWrite 让硬件定时器持续输出 PWM，CPU 不参与每个周期——硬件外设的意义）

## 组合挑战（D2+D3 合体，强烈推荐）

- **按键调亮度**：D2 的按键 + D3 的 PWM——每次按下，亮度档位 +1（0→64→128→192→255 循环）
  - 提示：中断里只置标志，主循环改 `ledcWrite`
  - 这就是"旋钮/按键调光"的真实业务场景雏形（W3 会看到 0-10V/DALI 也是干这个）
