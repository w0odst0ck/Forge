## ADR-001｜2026-08-03｜W1 为什么用 ESP32 而非 Arduino Uno

- **决策**：W1-W4 仿真统一用 ESP32（Wokwi 的 esp32-devkit-v1）
- **理由**：
  1. 真实项目（智能照明网关）最终会用 ESP32 或 STM32——ESP32 有 WiFi/BLE，协议栈全（MQTT/DALI 生态成熟）
  2. Wokwi 对 ESP32 支持最好（虚拟示波器、逻辑分析仪、多外设）
  3. 与 W2 的 Python 侧 pymodbus 形成"ESP32 设备侧 + PC 上位机"的真实工程结构
- **替代方案**：Arduino Uno（5V 逻辑、8bit、无 WiFi）——学习简单但偏离目标架构；STM32（更接近工业）——仿真支持弱、上手陡
- **结论**：ESP32 是"学习目标 = 工程目标"的最小重合点

## ADR-002｜2026-08-03｜D5 传感器用 MPU6050 而非 BME280

- **决策**：I2C 教学用 MPU6050（六轴 IMU）
- **理由**：
  1. Wokwi 部件库没有 BME280（137 部件注册表实测）——硬需求
  2. MPU6050 是 I2C 教学经典：设备地址可配（0x68/0x69）、寄存器表清晰、仿真可交互改读数
- **替代方案**：DS1307（I2C RTC）——能教学 I2C 但"读时间"不如"读传感器"直观；DHT22——非 I2C（单总线），教学点错位
- **结论**：MPU6050 满足 I2C 教学目标，温湿度传感器的空缺由 W3 的"驱动规格书精读"补上（知识侧而非仿真侧）
