## 一、五层架构总图

```mermaid
graph TB
    subgraph 应用层["应用层 · 业务逻辑"]
        A1[场景调度<br/>课表联动/人来灯亮]
        A2[节能审计<br/>能耗统计/报告]
        A3[管理平台<br/>Web/App]
    end
    subgraph 平台层["平台层 · 数据处理"]
        P1[网关<br/>协议转换/边缘逻辑]
        P2[时序库<br/>能耗数据]
        P3[MQTT Broker<br/>消息总线]
    end
    subgraph 通信层["通信层 · 设备联网"]
        C1[DALI<br/>灯具级调光]
        C2[KNX<br/>楼宇级控制]
        C3[Modbus/RS-485<br/>工控/网关]
        C4[蓝牙Mesh/Zigbee<br/>无线]
    end
    subgraph 控制层["控制层 · 执行"]
        B1[调光驱动<br/>0-10V/DALI/PWM 输入]
        B2[继电器/回路控制器]
    end
    subgraph 感知层["感知层 · 采集"]
        S1[存在型雷达<br/>静止人体检测]
        S2[光照传感器<br/>恒照度]
        S3[面板/按键]
    end

    S1 --> B1
    S2 --> B1
    S3 --> C3
    B1 --> C1
    B1 --> C3
    C1 --> P1
    C3 --> P1
    C2 --> P1
    C4 --> P1
    P1 --> P3
    P3 --> P2
    P1 --> A1
    P2 --> A2
    A1 --> A3
```

**核心认知**：智能照明 = 感知（采数据）+ 控制（执行调光）+ 通信（联网）+ 平台（数据/逻辑）+ 应用（业务）。W1-W4 就是从底层往上爬：W1 摸透控制层和感知层的"手感"，W2 打通通信层，W3 深挖调光驱动，W4 组装平台层+应用层。

## 二、W1 demo ↔ 架构位置映射

| D | demo | 架构层 | 说明 |
|---|------|--------|------|
| D1 | GPIO 点灯 | 控制层 | "灯亮/灭"的最基本执行单元。LED = 一盏灯的抽象 |
| D2 | 按键中断 | 感知层 + 控制逻辑 | 输入设备接入 + 事件驱动处理 |
| D3 | PWM 调光 | 控制层（核心） | 调光驱动的底层机制，W3 深挖上层协议 |
| D4 | UART | 通信层 | 点对点链路——Modbus 的物理基础 |
| D5 | I2C 传感器 | 感知层 | 传感器数据采集，恒照度/人感的前提 |

## 四、架构理解自检（每 D 问自己）

1. 这个机制在系统图里属于哪一层？和上下层怎么协作？
2. 如果它坏了，影响范围多大？（故障域思维——架构师第一课）
3. 换一种方案做同一件事，代价是什么？（选型思维）
