# W1-D6 · 主线串讲：5 个 demo = 一个智能灯具

> 验证标准：能向别人讲清中断原理，能把 D1-D5 串成一个完整系统

## 一、主线叙事（回答"学这些干嘛"）

W1 的 5 个 demo 不是 5 件孤立的事。把它们拼起来，**就是一个智能灯具的雏形**：

```
                    ┌─────────────────────────────────────┐
                    │           智能灯具 = 4 个角色          │
                    │                                     │
  人/环境 ──感知──▶ │ 输入：按键(D2) + 传感器(I2C, D5)      │
                    │         ↓ 数据                       │
                    │ 大脑：ESP32（GPIO/中断/时序）          │
                    │         ↓ 决策                       │
                    │ 输出：LED（GPIO D1 + PWM 调光 D3）    │
                    │         ↕ 对外通信                    │
                    │ 通信：UART(D4) → 网关 → 平台           │
                    └─────────────────────────────────────┘
```

对照真实智能照明系统的映射：

| W1 demo | 真实系统里的角色 |
|---------|-----------------|
| D1 GPIO 点灯 | 灯亮/灭的基础控制 |
| D2 按键中断 | 面板开关/人感信号接入 |
| D3 PWM 调光 | **调光驱动**（W3 深挖 0-10V/DALI 的上层协议，底层都是它）|
| D4 UART | **网关与设备的通信链路**（W2 换成 Modbus 工业标准）|
| D5 I2C 传感器 | 恒照度/人感联动/能耗数据回传 |

**核心认知**：智能照明 = 传感器（感知）+ 控制逻辑（决策）+ 调光驱动（执行）+ 通信协议（联网）。W1 让你亲手摸过这四个角色各一次，W2-W4 是把每个角色换成"工业级"实现。

## 二、中断原理完整讲解（D6 验收标准）

### 2.1 什么是中断

CPU 平时在主循环里"排队干活"（轮询）。中断 = 硬件事件插队——按键按下、串口收到字节、定时器溢出，**硬件自动打断主循环，跳去执行 ISR，执行完再回到断点继续**。

```
主循环:  [干A]  [干B]  [干C]  [干D]  [干A] ...
                    ↑ 按键按下（硬件触发）
                    └→ 保存现场 → 执行 ISR → 恢复现场 → 从断点继续
```

### 2.2 为什么需要中断

轮询的问题：主循环忙的时候（比如调光渐变要延时 1.3s），按键按下要等 loop 转一圈才被看见——**实时性差**。中断让"重要事件"不管主循环在干嘛都能立即响应。

### 2.3 中断的规则（面试重点）

1. **ISR 要短**：ISR 执行期间，其他中断和主循环全部挂起。ISR 里 delay = 系统卡死
2. **ISR 里只置标志，主循环消费**：数据传递用 volatile 变量
3. **volatile 必须有**：防编译器把变量缓存进寄存器，导致主循环读不到 ISR 的更新
4. **共享资源防冲突**：ISR 和主循环同时操作的数据要加保护（W2 以后会遇到互斥锁）

### 2.4 一图记住 D1-D5 的时序概念

| 概念 | 时间尺度 | 例子 |
|------|---------|------|
| GPIO 电平 | 纳秒级翻转 | D1 点灯 |
| 中断响应 | 微秒级（硬件自动） | D2 按键 |
| PWM 周期 | 0.1ms 级（5kHz） | D3 调光 |
| UART 位时序 | 波特率决定（9600 = 104μs/bit） | D4 通信 |
| I2C 时钟 | SCL 频率决定（100k/400kHz） | D5 传感器 |
