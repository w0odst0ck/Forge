# W1-D2 · 按键中断 + 防抖

> 验证标准：按下按键，串口打印正确；快速连按无抖动误触发

## 操作步骤

1. `sketch.ino` 粘贴到 Wokwi 代码编辑器
2. `diagram.json` 粘贴生成电路：ESP32 + 按键（D4 ── 按键 ── GND）
3. 点 ▶ 运行，Serial Monitor 看到 `Ready. Press the button!`
4. 点击仿真里的按键（或键盘 1）：每次按下打印一行 `Button pressed! (debounced)`
5. 快速连按：不会出现"一次按下打印两行"的抖动误触发

## 电路

```
ESP32 D4 ── 按键 ── GND
（内部上拉：不按时 D4 读到 HIGH，按下 = LOW）
```

- 为什么不用外部上拉电阻？ESP32 引脚内置可配置上拉（`INPUT_PULLUP`），省一个电阻
- 按键另一端接 GND 而非 3V3，是为了用**下降沿**（FALLING）触发——按键释放瞬间的抖动影响更小

## 概念速记

| 概念 | 要点 |
|------|------|
| 轮询 vs 中断 | 轮询：主循环反复查状态（简单但浪费 CPU）；中断：硬件事件来了打断主循环执行 ISR（实时响应）|
| ISR | 中断服务函数。规则：**短**、不 delay、不做耗时操作（打印/内存分配）|
| volatile | ISR 里改、主循环读的变量必须 volatile——防止编译器把它优化进寄存器 |
| 防抖 | 机械按键按下瞬间有 ~10ms 抖动（高低电平反复跳变），用时间戳过滤：距上次触发 <50ms 的忽略 |
| FALLING | 触发模式：信号从 HIGH 变 LOW 的瞬间触发（上拉接法按下的边沿）|
| IRAM_ATTR | ESP32 的 ISR 加此修饰，代码放 IRAM 避免 Flash 访问冲突（WiFi 等场景必须）|

## 面试式验证问题（能答出 = 真学会）

1. **中断服务函数里为什么不能放 `delay()`？**（ISR 执行期间主循环和低优先级中断全被挂起；delay 是忙等，会让系统"卡死"在 ISR 里，且超过阈值触发看门狗复位）
2. **`volatile` 是干什么的？不加会怎样？**（编译器优化：把变量读进寄存器缓存，主循环可能永远读不到 ISR 的更新值）
3. **防抖为什么用"时间戳过滤"而不是"延时再读"？**（延时是阻塞的，浪费 CPU；时间戳过滤只记录时刻，主循环零阻塞）
4. **如果按键接到 3V3（按下 = HIGH），触发模式该用哪个？**（RISING；但上拉到 3V3 的接法松开瞬间抖动更糟，所以工程惯例是下拉/上拉接地）
